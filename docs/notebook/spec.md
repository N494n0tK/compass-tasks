# チャートノート統合 仕様書（compass-note@2）

Compass-Tasks に「授業ノート ＋ 想起カードの間隔反復」を統合するための正典。
実装は本書のチェックリスト **N-001〜N-137** を全て満たすこと。

> **v0.14（2026-08-10）で AI の役目が反転した。** それまでは「ノートの写しは禁止・
> 書いていないことだけを補う」だったが、いまは **AI が自分の手書きノートを
> コーネル式まとめノートとして再現し、そこへ添削（赤入れ）をする**（§3.8）。
> 貼り付け JSON は `compass-note@2`。`@1` も移行規則付きで受理する（§3.9）。

関連: [../rewrite/architecture.md](../rewrite/architecture.md) / [../rewrite/app-spec.md](../rewrite/app-spec.md) §6（復習）・§4.9（時間割）

---

## 1. 目的とワークフロー

`CompassNotebook/` の「チャートノート v2 / v3」（依存欠落で単体動作しない dc-html）を Next.js へ作り直し、
Compass の既存復習エンジンへ接続する。ユーザーが到達したい状態:

| # | 段階 | 担当 |
|---|---|---|
| 1 | 授業を録音し、ノート・スライドを写真に撮る | 自分 |
| 2 | 文字起こしと写真を **1 本のプロンプト**と一緒に AI に渡す → JSON | 外部AI |
| 3 | JSON を Compass に貼る。検証が通れば保存 | 自分（貼るだけ） |
| 4 | 貼ったその日の ToDo に、そのノートの復習が 1 枚積まれる | Compass |
| 5 | 「ノートで復習」→ その授業の問題だけのドリルで想起問題に答える | 自分 |
| 6 | 完了すると次の間隔へ送られる | Compass |
| 7 | 予習が時間割から自動で積まれる | Compass |

## 2. 用語

| 語 | 意味 |
|---|---|
| ノート（Note） | 授業1回分。`users/{uid}/notes/{noteId}` に1ドキュメント |
| カード（NoteCard） | ノート内の想起問題1問。復習の最小単位 |
| 系列（series） | 1カードに対応する復習の連なり。`seriesId` で束ねる |
| 区画（NoteSection） | 本文の1かたまり。`text`＝自分のノートの再現、`ai`＝そこへの添削 |
| 添削（`section.ai`） | AI の赤入れ。誤りの訂正と、ノートに無い重要点だけ |
| 演習（exercise） | ノート末尾の仕上げ1問。**カードにはしない** |

## 3. データモデル

### 3.1 保存形（`src/lib/model/notes.ts`）

```ts
export const NOTE_SCHEMA = 'compass-note@2';
export const NOTE_SCHEMA_V1 = 'compass-note@1';   // 取り込みでは受理する（§3.9）

export type NoteCardOrigin = 'self' | 'ai';

export interface NoteCard {
  cardId: string;   // 'c' + base36。取り込み時に採番し、以後不変
  q: string;        // 問題文（$...$ / $$...$$ の LaTeX 可）
  a: string;        // 解答
  guide: string;    // 方針（空文字可）
  src: string;      // 出典（空文字可）
  origin: NoteCardOrigin;  // 'self' = 自分がノートに書いた問い
}

export const NOTE_KEY_COLORS = ['red','blue','green'] as const;   // 3色（§3.5）
export type NoteKeyColor = (typeof NOTE_KEY_COLORS)[number];

export interface NoteKeyword {
  term: string;        // 本文に出てくる文字列と1文字も違えない
  color: NoteKeyColor;
  note: string;        // キュー欄に添えるひとこと（空文字可）
}

export interface NoteSection {
  heading: string;  // 自分のノートの見出し（無ければ ''）
  text: string;     // **自分のノート本文の再現**。'' なら AI の補足だけの区画
  ai: string;       // その区画への添削（'' なら無し）
}
export const NOTE_SECTION_MAX = 24;

export interface Note {
  id: string;       // 'n' + base36 + rand。Firestore の doc id
  v: 1;
  date: ISODate;    // 授業日
  subject: string;
  unit: string;
  scans: NoteScan[];       // 自分で撮った写真のメタデータ（§6.2）
  cards: NoteCard[];
  sections: NoteSection[]; // 本文。自分のノートの再現 ＋ 各区画への添削
  summary: string;         // コーネル式の下段。**自分がノートに書いたまとめ**（無ければ ''）
  keywords: NoteKeyword[]; // コーネル式の左段（キュー欄）に並ぶ重要語
  exercise: { q: string; a: string };
  doubt: string;           // 自分がノートに書いた疑問だけ。1行1件
  notice: string;
  createdAt: ISODate;
  updatedAt: ISODate;
}
```

`cardId` を持つのが v2/v3 との唯一の本質的な差。旧実装は解説ブロックを `qi`（recall の配列インデックス）で
指しており、想起問題を1つ消すと全ての `qi` がズレる潜在バグがあった。取り込み時に `qi → cardId` へ解決する。

`summary` / `keywords` / `origin` は v0.12 で足した（§3.5 / §3.6）。**旧ノートには無い**ので、
`sanitizeNotes`（`NotebookPersistence.ts`）が既定値（`''` / `[]` / `'ai'`）を埋めて読む。移行スクリプトは要らない。
`sections` は v0.14 で `blocks` を置き換えたもの。保存済みノートの `blocks` も
読み込みのときに `sections` へ畳む（§3.9）。ここでも移行スクリプトは要らない。

### 3.2 貼り付け JSON（外部AI が出力する形）

```json
{
  "schema": "compass-note@2",
  "date": "2026-08-06",
  "subject": "数学",
  "unit": "数列 ─ 漸化式と一般項",
  "recall": [{ "q": "…", "a": "…", "guide": "…", "src": "…", "origin": "self" }],
  "sections": [{ "heading": "基本 3 型", "text": "① …\n② …", "ai": "③ は差が $n$ の式のとき" }],
  "keywords": [{ "term": "漸化式", "color": "red", "note": "隣の項の関係式" }],
  "summary": "…",
  "exercise": { "q": "…", "a": "…" },
  "doubt": "…",
  "notice": "…"
}
```

| 欄 | 誰のものか | 規則 |
|---|---|---|
| `sections[].text` | **生徒** | ノート本文の忠実な再現。1行1事項（`\n` 区切り）。AI は書き足さない |
| `sections[].heading` | 生徒 | ノートの見出しそのまま。無ければ `""` |
| `sections[].ai` | **AI** | その区画への添削。(a) 誤りの訂正 (b) ノートに無い重要点。2〜3行まで |
| `recall[].origin` | 両方 | `"self"` = 生徒がノートに書いた問い（先に並べる） / `"ai"` = AI が補った分 |
| `keywords[].color` | AI | `red` / `blue` / `green` の**3色だけ**（§3.5） |
| `summary` | **生徒** | AI は**常に `""`**。復習のときに本人が書く欄（転記もさせない） |
| `doubt` | **生徒** | ノートに書かれた疑問だけ。1行1件。無ければ `""` |

- `text` と `ai` が両方 `""` の区画は**無効**（見出しだけの区画は紙面で浮くので落とす）
- ノートに無い AI だけの補足は `{ "heading": "…", "text": "", "ai": "…" }` の形で置く
- 区画は最大 **24**（`NOTE_SECTION_MAX`）。超えた分は切り落として warning
- ノートの写真が無い回は `text` を作らせない。録音から分かることを `text: ""` の区画に置く
  （**ノートを捏造させない**のがこのスキーマの一番の目的）

### 3.3 バリデーション（`src/lib/logic/noteImport.ts`）

`parseNoteJson(text, { today, existing?, newId? })` →
`{ ok: true, note, warnings, diff? } | { ok: false, errors }`。
issue は `{ path: 'recall[2].a', message: '解答が空です' }`。**エラーが1件でもあれば保存しない。**

| path | 条件 | 種別 | メッセージ |
|---|---|---|---|
| `$` | `JSON.parse` 失敗 | error | `JSONとして読み取れません: <理由>` |
| `$` | 配列 / 非オブジェクト | error | `JSONのトップレベルはオブジェクトにしてください` |
| `$` | コードブロック / 前置きが付いている | warning | `コードブロックや前後の文章を取り除いてから読み込みました` |
| `schema` | 欠落・空 | warning | `schema が無いので "compass-note@2" として読み込みました` |
| `schema` | `compass-note@1` | — | 旧形式として読む（§3.9。エラーにも warning にもしない） |
| `schema` | それ以外の値 | error | `schema は "compass-note@2" にしてください（受信: …）` |
| `date` | `YYYY-MM-DD` でない（空文字を除く） | warning | `date の形式が不正なので今日の日付にしました` |
| `subject` | 空 | error | `教科を入力してください` |
| `subject` | `knownSubjects` に無い | warning | `教科「…」は時間割にありません（…）。ノートの「編集」から選び直せます` |
| `unit` | 空 | error | `単元名を入力してください` |
| `recall` | 配列でない / 0件 | error | `recall を1件以上入れてください` |
| `recall` | 8件超 | error | `recall は8件までです（受信: N件）` |
| `recall[i].q` | 空 | error | `問題文が空です` |
| `recall[i].a` | 空 | error | `解答が空です` |
| `sections` | 配列でない（キーはある） | **error** | `sections は配列にしてください` |
| `sections[i]` | オブジェクトでない | warning | `セクションの形式が不正なので無視しました` |
| `sections[i]` | `text` も `ai` も空 | — | 黙って落とす（見出しだけの区画は紙面で浮く） |
| `sections` | 24区画超 | warning | `本文は24区画までなので、先頭から採用しました` |
| `blocks` | `@1` の旧本文 | — | `sections` とカードの `guide` へ畳む（§3.9） |
| `blocks[i].t` | `def`/`ex` 以外 | warning | `未知のブロック種別 "…" を無視しました` |
| `blocks[i].qi` | 範囲外 | warning | `qi=N は recall の範囲外なので未対応にしました` |
| `exercise` | 非オブジェクト | warning | `exercise を読み取れないので空にしました` |
| `recall[i].origin` | `"self"` 以外 | — | 黙って `'ai'` にする |
| `keywords` | 配列でない | warning | `keywords を配列として読み取れないので空にしました` |
| `keywords` | 24語超 | warning | `重要語は24語までなので、先頭から採用しました` |
| `keywords[i]` | 空 `term` / 重複 / 文字列以外 | — | 黙って落とす（文字列の配列でも読む） |
| `keywords[i].color` | 3色以外 | — | 黙って寄せる（`@2` は `'red'`、`@1` は §3.9 の対応表） |

`sections` が**配列でない**ときだけエラーにするのは、`sections` が `@2` の本文そのものだから。
黙って空にすると「取り込めたのにノートが白紙」という一番たちの悪い失敗になる。
**キーごと無い**のは AI がよく落とすだけなので、他の欄と同じく空で通す。

`date` / `sections` / `exercise` / `summary` / `keywords` / `doubt` / `notice` は欠落を warning 無しで既定値に落とす（`date` のみ形式不正時に warning）。
生成 AI の出力ゆらぎをどこまで飲むかは §7.3 にまとめてある。

### 3.4 上書き取り込み（`existing` あり）

`id` / `createdAt` を維持し、`cardId` は**インデックスで**既存カードに対応付ける。
差分 `{ keptCardIds, addedCardIds, removedCardIds }` を返し、呼び出し側が復習をカスケードする。

### 3.5 重要語とキュー欄（`src/lib/logic/noteKeywords.ts`）

コーネル式ノートの左段（キュー欄）にあたる。`keywords` を本文（`sections`）に**部分文字列一致**で当て、

- 本文では色を塗る（`.nb-key--<color>`）
- キュー欄では「その語が**初めて出てくる区画**」の行に並べる（`assignCues`）
- 確認モードでは本文側だけを付箋で伏せる（`.nb-key.is-hidden`）

の 3 つに使う。探す先は 1 区画ぶんの `heading` + `text` + `ai` をつないだ文字列
（`sectionSearchText`）―― 重要語は自分の本文にも添削にも出てよい。
ひとつの語をキュー欄に出すのは 1 回だけ（2 回目以降の出現でも並べると左段が埋まる）。
一致は常に**長い語から**当てる（`splitByKeywords`）。日本語には語境界が無く、「革命」が
「産業革命」を食ってしまうため。本文に見つからない語は捨てずに `orphans` に落とし、
キュー欄の末尾にまとめて出す（編集モードでは赤枠で「本文に見当たりません」と告げる）。

**色は 3 つだけ**（v0.14。まとめノートの 3 色ルール）。役割を固定した 3 色で、
プロンプトにも同じ対応表を書いてある。

| color | 役割 | 例 | テーマ変数 |
|---|---|---|---|
| `red` | **最重要**（用語・定義） | 漸化式 / 仮定法過去 | `--pink` |
| `blue` | **事実**（人物・年号・固有名詞・数値） | ワット / 1760 / were | `--blue` |
| `green` | **つながり**（因果・対比・例外） | 帰着 / ⇔ の相手 / 別に確認 | `--grn` |

5 色（`orange` = 因果・変化、`purple` = 対比・例外）をやめた理由:

- 紙面で**見分けが付かない**。オレンジと赤、紫と青が溶ける（特に `light` の紙）
- 色数が増えるほど「この色は何の意味だったか」を思い出す手間が増え、
  読むための色が読むことの邪魔になる。まとめノートの通説どおり**役割固定で3色まで**にする
- AI も 5 色を撃ち分けられず、実際の出力は red に偏るか、意味と関係なく散っていた

旧 5 色は取り込み・読み込みで畳む（§3.9）。明るい紙（`data-theme="light"`）では
3 色とも `color-mix` で 1 段沈める（[E-2] の注記。実測 6:1 以上）。

### 3.6 「自分のもの」と「AI のもの」

コーネル式は**問いを立てるのが自分**であることに意味がある。だから:

- `sections[i].text` … 生徒のノートの再現。AI は写すだけで、書き足さない。
  ノートに無いことは `ai`（添削）に回す（§3.8）。
- `recall[i].origin === 'self'` … 生徒がノートに書いた問い。プロンプトは**1問も落とさず**拾い、先に並べる。
  紙面では「自作」の版を張る（AI 作は輪郭だけの「AI」）。編集画面から足した問いは常に `self`。
- `doubt` … 生徒がノートに書いた疑問**だけ**。プロンプトは「あなたが分かりにくいと思った点は書かない」と
  明示的に禁じる。該当が無ければ空文字のまま。紙面では 1 行 1 件の箇条書き（`.nb-doubt`）。
- `summary` … **AI は常に空文字で返す**（v0.15 で変更。v0.14 の「ノートのまとめを転記する」もやめた）。
  ここは**復習のときに本人が書く欄**で、AI は要約も転記も入れない ―― まとめは
  「自分の言葉で言い直す」ことに効き目があるのであって、代わりに言い直してもらっては意味がない。
  先に埋まっていると、書き直す機会そのものが無くなる。
  ノートに「まとめ」「結論」と書かれた部分があるときは、`sections` の 1 区画
  （`heading: "まとめ"`）として本文に再現する。情報は落とさず、置き場所だけを分ける。
  だから紙面でも**「自分のノートだけ」レンズで畳まない**（§8.3）。

  取り込みの含み: AI が常に空を送るので、**上書き取り込みで空を受けたら既存の `summary` を引き継ぐ**
  （`noteImport.ts`。写真と同じ扱い）。そうしないと JSON を貼り直すたびに、
  自分で書いたまとめが黙って消える。

### 3.7 教科は時間割の名前に揃える

`subject` の候補は**時間割（`logic/timetable.ts` の `timetableSubjects()`）から取る**。
固定の一覧（数学・英語・国語・理科・社会…）を持たない。

大分類を候補にしていたときは、AI が「社会」「理科」と答え、時間割の「歴総 / 地総 / 化基 / 生基」と
食い違っていた。教科名は**教科の色（`subjectColorFor`）と予習の突き合わせ（`prepAutogen`）の
つなぎ目**なので、ズレると両方が壊れる。

| どこ | どうする |
|---|---|
| プロンプト | `noteMainPrompt(subjects)` が一覧を埋め込み、「大分類は使わない」と明示。自己チェック 9 番 |
| 取り込み | `parseNoteJson(..., { knownSubjects })`。一覧に無ければ **warning**（エラーにはしない） |
| 紙面 | 一覧に無い教科には「時間割にない教科」の版を出す |
| 編集 | 教科チップが時間割の一覧 ＋ `その他`。いま付いている名前が一覧に無ければそれも残す（直せなくなるため） |

時間割に無い授業（補講・自習など）のノートも取れるべきなので、**エラーにはしない**。

### 3.8 AI は「ノートの再現」と「添削」（v0.14 で反転）

**v0.13**: AI の役目は「ノートの余白」だった ―― ノートに書いてあることを**書き写すのを禁止**し、
録音・スライドにあってノートに無い要点（`blocks[].t === 'def'`）だけを書かせていた。
本文は写真（`scans`）が持ち、AI は付箋として脇に付く、という配分。

**v0.14（いま）**: これを反転させる。AI はまず**自分の手書きノートを
コーネル式まとめノートとして忠実に再現**し（`sections[].text`）、そのうえで
区画ごとに**赤入れ（`sections[].ai`）**をする。

なぜ反転したか:

- 写真は**読み返せるが検索も復習もできない**。重要語の色付け・確認モード・
  キュー欄はテキストにしか効かず、紙面の主役だけが仕組みの外にあった
- 「余白」だけを読んでも授業の筋が辿れない。断片の付箋が 4 枚並ぶだけだった
- ノートを起こしてもらうと、**自分が何を書き落としたか**が添削と並んで見える。
  これは写真を見比べるより速い

| AI が書くもの | どこに入るか | 制約 |
|---|---|---|
| **自分のノート本文の再現** | `sections[].text` | 文言・語順・並び順のまま。教科書調に書き換えない。**ノートに無いことを混ぜない** |
| 誤りの訂正 | `sections[].ai` | 「ノートは○○だが正しくは××」。1区画 2〜3 行まで |
| ノートに無い重要点（録音・スライド由来） | `sections[].ai`、または `text:""` の区画 | `text:""` の補足区画は多くて 4 件 |
| 想起問題と解答 | `recall`（`origin:"ai"`） | 生徒の自作問題（`self`）を先に、足りない分だけ |
| 重要語 | `keywords` | 6〜12 語・**3 色**（§3.5） |

AI が**書かないもの**: `summary`（**常に空**。復習のとき本人が書く欄）と
`doubt`（生徒がノートに書いた疑問だけ。無ければ空）。どちらも AI が発明してはいけない（§3.6）。

明らかな誤字・脱字だけは `text` で黙って直す。**内容の誤りは `text` で直さない** ――
直してしまうと「自分は正しく書けていた」ことになり、添削の意味が消える。
ノートの写真が無い回は `text` を作らせない（録音から分かることを `text:""` の区画に置く）。

プロンプトは冒頭で「あなたの役目はノートの**再現**と**赤入れ**」と宣言し、
自己チェックの 1 番を「`text` にノートに書いていないことが混じっていないか」にしてある（§7.2）。

`Note.scans`（写真）は残る。ただし**主役ではなく原本の控え**になり、紙面では畳んでおく（§8.3）。
メタデータだけ（`scanId` / `mime` / `w` / `h` / `bytes` / `caption`）で、
画像の実体は §6.2 のとおり端末の IndexedDB に置く。

### 3.9 `@1` → `@2` の移行規則

**貼り付け JSON（`@1`）も、保存済みノート（`blocks` を持つドキュメント）も同じ規則で読む。**
入口は `noteImport.ts` の `migrateLegacyBlocks` 1 か所（取り込みと読み込みで共用）。
移行スクリプトは走らせない ―― 読むたびに畳めば足りる。

`schema` が `compass-note@1` のとき、または `schema` が無く `sections` が無くて
`blocks` があるとき（旧プロンプトの出力）を**旧形式**とみなす。

| `@1` | `@2` | 理由 |
|---|---|---|
| `blocks[].t === 'def'` | `{ heading: title, text: "", ai: body }` | 旧 `def` は「ノートに書いて**いない**こと」。自分の本文ではなく添削として置く |
| `blocks[].t === 'ex'`（対応カードあり） | そのカードの `guide` に追記 | 方針・解答・注意は問題の隣で読むもの。本文に置くと問題から離れる |
| `blocks[].t === 'ex'`（`qi` が範囲外 / `null`） | `{ heading: "解説", text: "", ai: … }` | 捨てると内容が黙って消える |
| 上記で中身が空になった区画 | 落とす | `sections` の規則（`text` も `ai` も空は無効）に揃える |

重要語の色（旧 5 色 → 3 色）。**旧データと分かっている入口でだけ**この表を通す:

| `@1` | `@2` | 理由 |
|---|---|---|
| `orange`（因果・変化） | `green`（つながり） | 因果はいまの「つながり」そのもの |
| `purple`（対比・例外） | `blue`（事実） | `orange` と両方 `green` に畳むと旧ノートが green 一色になる。対比・例外は「ただし」「一方」で結ばれる具体例に付いていたので事実側へ振る |
| `green`（年号・数値） | `blue`（事実） | 旧 `green` は数値。新 `green`（つながり）とは**別物** |
| `red` / `blue` | そのまま | 意味が重なる |
| 知らない値・欠落 | `red` | 取り込みを止めない |

`@2` として読むときは `orange → green` / `purple → blue` だけを当て、`green` はそのまま
（`normalizeKeyColor`）。旧 `green` を `blue` に読み替えるのは `@1` のときだけ
（`migrateLegacyKeyColor`）―― 同じ `green` という文字列が版によって別の意味を持つため、
入口を分けないと新しいノートの「つながり」まで青くなる。

## 4. ノート ↔ 復習の連携

**`Review` 型・`reviews.ts`・`dataPatch.ts` は一切変更しない。** リンクは `seriesId` の命名規約だけで表す:

```ts
noteSeriesId(noteId, cardId) === 'nb-' + noteId + '-' + cardId
noteRefOf(seriesId) → { noteId, cardId } | null    // /^nb-(n[0-9a-z]+)-(c[0-9a-z]+)$/
```

`nextReviewOf` は `seriesId: review.seriesId || review.id` を無条件で継承するので、
段階が進んでもリンクは切れない。カスタムフィールドを足す案は段階遷移で落ちるため採らない。

### 4.1 生成（`generateNoteReviews(note, existing, today)`）

カードごとに、同じ `seriesId` を持つ行が **1件も無いときだけ** 1件作る（再取り込みで増えない）。

**授業が終わってノートを貼ったら、その日のうちに復習する。** だから初回は `due` が今日で、
最初から今日の ToDo に積まれる（`added: true`）。段階は `'当日'` から始まる。

| フィールド | 値 |
|---|---|
| `id` / `seriesId` | `noteSeriesId(note.id, card.cardId)`（初回は一致。手動追加と同型） |
| `reviewNo` | `1` |
| `title` | `note.unit + ' 問' + (index + 1)` |
| `subj` | `note.subject` |
| `stage` / `last` / `due` | `'当日'` / `today` / `today` |
| `min` | `5`（XS） |
| `src` | `'ノートから生成'` |
| `timetablePeriod` / `timetableDate` | `null` / `null` |
| `added` / `done` | **`true`** / `false` |

はしごは **当日 → 翌日 → 3日後 → 1週間後 → 2週間後 → 定着** の 5 段。
`'当日'` は `lib/logic/reviews.ts` の `STAGE_NEXT` に 1 行足しただけで、既存の 4 段は不変
（手動追加・時間割からの復習は従来どおり `'翌日'` 始まり）。`'当日'` だけは
**まあまあ でも翌日へ送る**（据え置き = 「今日もう一度」は今日の ToDo と噛み合わないため）。

### 4.2 今日の ToDo では 1 冊 1 枚（`ShellTodayItems.collapseNoteReviews`）

想起問題ごとに独立した系列を持つ設計はそのままに、**今日の ToDo の見た目だけ**ノート単位に束ねる。

- タイトル … ノートの単元名（`note.unit`）
- 分数 … 束ねた行の合計、完了 … **全問終わって初めて完了**
- `src` … `'ノートの復習 · 2/3問'`（残り / 全体）
- カードをクリック or 「ノートで復習」 → **ドリル面**（§8）へ。1 問ずつ理解度モーダルは開かない
- `state.notes` にノートが無い（未読込・削除済み）行は束ねず、従来どおり 1 問 1 枚

束ねるのは `buildTodayItems` の 1 か所だけなので、トップバーのカウンタ・コックピット・
ToDo・集中モードがすべて同じ見え方になる。seg / extra / 手動の復習には一切触れない。

### 4.3 同期・カスケード

- `syncNoteReviews(note, reviews)` — カードを維持したままノートを編集したとき、**未完了行のみ** `title` / `subj` を更新
- `cascadeNoteRemoval(reviews, order, selId, noteId, cardIds?)` — **未完了行のみ削除**、`order` から除外、`selId` を null 化。
  完了行は学習履歴として残す（`studyLog` は既に書かれている）

## 5. 予習の自動生成（`src/lib/logic/prepAutogen.ts`）

- `nextSchoolDay(today)` — `today` より後の最小の月〜金。金→月、土→月、日→月
- 対象日の時間割 = `TIMETABLE[dowOf(target)]` に `dayOverrides[target]` を適用（`held === false` は休講で除外、`subj` は差し替え）
- **教科ごとに1件**（同じ教科が2コマあっても予習は1件。`timetablePeriod` は最初のコマ）
- `prepAutoGen.offSubjects` に入っている教科は除外
- `prepGenLog[target]` に記録済みのコマは再生成しない（**ユーザーが消したタスクを翌起動で復活させない**）
- ログは 14 日より古いキーを削除する

生成する `Extra`:

```ts
{ id: 'u'+base36+rand, title: subj + 'の予習', subj, size: 'S', min: 10,
  day: today, done: false, src: '予習 · ' + fmtMD(target) + ' ' + period + '限(自動)',
  timetablePeriod: period, timetableDate: target }
```

設定 `prepAutoGen: { enabled: boolean; offSubjects: string[] }`（既定 `{ enabled: true, offSubjects: [] }`）と
`prepGenLog: Record<ISODate, number[]>` を **`PERSISTENT_KEYS` の末尾に追記**する（並べ替え厳禁）。

トリガーはアプリ起動時、クラウド読込が終わって `cloudStatus` が `'loading'` を抜けた直後の1回だけ。

### 6.2 ノートの写真（`NoteScanStore`）

写真の実体は**端末の IndexedDB**（`compass-note-scans` / ストア `scans` / キー `noteId:scanId`）。

| 置けない先 | 理由 |
|---|---|
| Firestore のノートドキュメント | 1 ドキュメント 1MB 上限。スマホの写真 1 枚で超える |
| localStorage | 文字列だけ・5MB 前後 |
| Firebase Storage | このプロジェクトでまだ有効化していない |

取り込み時に長辺 2000px まで縮め、JPEG 品質 0.82 に焼き直す（`prepareScan`）。
ノートの字が読める解像度を保ちつつ、1 授業ぶんが数百 KB に収まる。

**割り切り**: 写真は撮った端末にしか無い。ノートのドキュメントには
メタデータ（枚数・寸法・見出し）だけが載るので、別の端末では枠と枚数は見えるが
中身は「この端末に写真がありません」と出る（§12-6）。`objectUrl()` はモジュール内で
`blob:` URL をキャッシュする（再レンダーごとに作ると解放されず積み上がる）。

## 7. プロンプト

外部 AI に渡すテンプレート。**1 本だけ**（v0.10.1 で 2 段構成をやめた）。
実体は `src/components/parts/NotePrompts.ts` の `NOTE_PROMPT_BODY`。**全文はそちらを正とする**
（二重管理すると必ずずれるので、本節には要点だけ置く）。

> **長さの上限 8000 文字。** このプロンプトは ChatGPT の GPT ビルダーの「指示」欄に
> 丸ごと貼って使う。同欄は 8000 文字までで、超えると**保存がブロックされる**
> （実際に 8539 文字で弾かれた）。教科名は時間割から埋め込まれるので、
> 本文をいじらなくても時間割が増えれば伸びる。予算は**余白込みで 7900 文字**とし、
> `noteMainPrompt(timetableSubjects())` の長さを vitest で固定してある
> （`parts/__tests__/NotePrompts.test.ts` / N-133）。
> 溢れたときに縮めてよいのは**「# 記入例」だけ** ―― 形式の見本なので、
> 規則を 1 つも失わずに縮められる唯一の場所。規則文と自己チェックは削らない。

### 7.1 なぜ 1 本にしたか

当初は プロンプトA（文字起こし＋写真 → 構造化Markdown）→ プロンプトB（Markdown → JSON）の 2 段だった。
実運用で機能しなかったので 1 本に統合した。原因:

- 1 段目の要約で板書の数式や細部が落ち、2 段目が「無い情報から JSON を作る」ことになっていた
- 画像を見られるのは 1 段目だけ。2 段目は元資料を参照できない
- 手数が倍で、途中の Markdown を貼り忘れる事故が起きやすい

### 7.2 プロンプト本体（文字起こし＋ノート/スライド画像 → compass-note@2 JSON）

要点:

1. 出力は JSON オブジェクト 1 個だけ。最初が `{`、最後が `}`。`schema` は `compass-note@2`
2. 冒頭で役目を宣言する ―― **「あなたの役目はノートの再現と赤入れ」**（§3.8）。
   続けて「本文（`text`）は生徒のもの、添削（`ai`）はあなたのもの」を欄ごとの表で示す
3. `sections[].text` は**ノート本文の忠実な再現**。文言・語順・並び順のまま、
   1 行 1 事項（`\n` 区切り）、教科書調に書き換えない、**ノートに無いことを混ぜない**。
   明らかな誤字だけ黙って直し、**内容の誤りは直さず `ai` に書く**
4. `sections[].ai` は (a) 誤りの訂正 (b) ノートに無い重要点 の 2 つだけ。1 区画 2〜3 行、
   無ければ空文字。ノートに無い補足だけの区画は `{heading, text:"", ai}`（多くて 4 件）。
   **ノートの写真が無い回は `text` を作らない**
5. まとめノートの流儀を明示する: 1 行 1 事項 / 対比は「⇔」/ 因果は「→」/ 見出しで階層化 / 詰め込まない
6. **生徒のものと AI のものを分ける**（§3.6）。冒頭で宣言してから、各項目で繰り返す
   - ノートに自分で書いた問いは 1 問も落とさず `origin:"self"` で、self を先に並べる
   - `doubt` は生徒が書いた疑問だけ。「あなたが分かりにくいと思った点は書かない」と明示的に禁じる
   - `summary` は**常に空文字**。要約も転記も禁じる（復習のとき本人が書く欄。§3.6）。
     ノートに書かれたまとめは `sections` の 1 区画として本文に再現させる
   - 足りないぶんだけ `origin:"ai"` で補って合計 5 問
7. `keywords` は 6〜12 語。**`term` は `sections` の本文に出てくる文字列と 1 文字も違えない**
   （一致検索で色を塗るため）。色は §3.5 の **3 色**の対応表そのままを指示し、
   「orange / purple は使わない」と名指しで禁じる
8. **LaTeX のバックスラッシュは JSON 文字列として 2 個重ねる**（`\\dfrac`）。最頻出の失敗
9. 記入例を丸ごと載せる（few-shot）。形式の遵守率が体感で一番変わる。
   ただし**上限 8000 文字**に収めるため、例は recall 3 問（`self`×2 + `ai`×1）/
   keywords 5 語（3 色すべて）/ sections 4 区画（うち 1 つは `text:""` の AI 補足）に縮めてある。
   縮めた分は見出しで断る ―― 「問数・語数は減らしてある。実際は recall 5 問・keywords 6〜12 語」
10. 出力前の自己チェックリスト 14 項目。**1 番は「`text` にノートに書いていないことが
    混じっていないか」**（この 1 行がこのプロンプトの要）

全文は `NotePrompts.ts` を正とする（ここに二重管理しない）。編集したら本節の要点も更新すること。
実際の時間割で展開した貼付用の文面は、GPT ビルダーに貼る運用のため別途書き出す。

### 7.3 アプリ側で吸収するゆらぎ（`extractJsonObject`）

「JSON だけ出せ」と書いても、生成 AI は次をやる。前 2 つは機械的に落とせるので **warning で通す**:

| ゆらぎ | 扱い |
|---|---|
| コードブロック（```json … ```）で囲む | 剥がして読む（warning） |
| 「以下がJSONです」などの前置き・後書き | 最初の `{` 〜 最後の `}` を切り出す（warning） |
| `schema` 行を忘れる | `compass-note@2` とみなす（warning）。`blocks` があれば旧形式として読む（§3.9） |
| `schema` に `compass-note@1` | 旧形式として受理（§3.9。warning も出さない） |
| `schema` に別の値（`chartnote-v2` 等） | **エラー**（別アプリ・別バージョンの JSON） |
| LaTeX のバックスラッシュを 1 個で書く（`\circ` など） | `repairJsonEscapes` で補って読む（warning）。**実際に踏んだ最頻出の失敗** |
| `qi: 0` と文字列で書く | 数値に寄せる |
| `date` を空文字にする | 今日の日付（warning なし。「読めなかった」の合図として指示済み） |
| 全角の引用符・末尾カンマ | **エラー**（直しようがない。行番号つきで表示） |

### 8.2 コーネル式の紙割り

```
┌ マストヘッド ────────────────────────────┐
│ 想起問題（自作を先に。「自作」「AI」の版）      │
├─ キュー欄 ─┬─ 本文 ─────────────────────┤
│ 重要語     │ 自分のノートの再現（区画ごと）   │  ← 縦罫 1 本（面の背景で引く）
│（初出の高さ）│ └ AI の添削（紫インク・字下げ）  │
├───────────┴────────────────────────────┤
│ まとめ（自分がノートに書いた言葉。無ければ出さない）│  ← 紙面いっぱいの上罫
├────────────────────────────────────────┤
│ 演習 / 疑問 / 連絡                          │
├────────────────────────────────────────┤
│ ▸ ノートの写真（原本）  ← 畳んである。開くと出る  │
└────────────────────────────────────────┘
```

**本文（`sections[].text`）が紙面の主役**（v0.14）。写真は原本の控えとして最下段に畳む（§8.3）。

Broadsheet の「枠で仕切らない」に対する**唯一の例外**。コーネル式は罫で紙を割ることが方式そのものなので、
縦罫（キュー欄と本文の境）と横罫（まとめの上）の 2 本だけ足す（`globals.css` の `[E-2]`）。
縦罫は行ごとの `border` ではなく `.nb-cornell` の背景グラデーションで引く ―― 段の切れ目で途切れさせないため。
狭い画面（700px 以下）ではキュー欄を各区画の上へ回し、縦罫はやめる。

**添削は本文に挟み込む**。区画の `text` の直後に、左罫 + 紫インク（`--nb-ai-ink`）+ `--f-ui` で
`ai` を出す（`.nb-aiedit`）。別の欄に集めない ―― 添削は「どの行に対する赤入れか」が
分からないと読めない。紫を使えるのは、重要語が 3 色になって紫が空いたから（§3.5）。
`text` が空の区画（AI だけの補足）は、本文の位置に紫インクだけで出る。

**確認モード**（`state.nbCheck`）。重要語が付箋で伏せられ、思い出してからクリックで 1 枚ずつめくる。
操作卓に「3 / 13」「全部めくる」「伏せ直す」。

- 伏せるのは `.nb-cornell` の中だけ。想起問題・まとめ・演習では色を塗るにとどめる
- **キュー欄の語も伏せる**（v0.14）。同じ語が左段に平文で並んでいると、本文を伏せても
  答えがすぐ隣にあることになり、確認にならなかった。キュー欄に残るのは `note`（ひとこと）で、
  それがヒントとして働く
- **めくった状態は DOM のクラスだけで持つ**（`is-hidden` を外す）。React state に置くと
  1 枚めくるたび `dangerouslySetInnerHTML` が貼り直され、剥がした付箋が戻る（実際に踏んだ）。
  枚数の表示も `ref` 経由で直接書き換え、確認モード中は再レンダーを一切起こさない
- 編集モード中は伏せない（伏せた語を書き換えられないため、`nbCheck && !nbEdit` で判定）

紙面スキン（ユーザー決定）:

| `data-theme` | 見た目 |
|---|---|
| `note` | v3 の紙ノート風（罫線・パンチ穴・付箋・Klee One） |
| `light` | v3 の紙ノート風（明るい紙） |
| `neon`（保存値 `dark`） | v2 のフラット活字風をダーク配色で |

復習の入口は 2 つあるが、間隔の計算はどちらも `ReviewShared.completeReview`
→ `lib/logic/reviews.ts` の 1 本道（フォーク禁止）:

1. **ドリル面**（既定）… 今日の ToDo のノートカード →「ノートで復習」。その授業の問題を続けて解く
2. **理解度モーダル**（従来）… 復習画面の行から 1 問だけ消化するとき。
   `noteRefOf(askR.seriesId)` でカードを引き、問題文と「答えを見る」を理解度ボタンの上に足す。
   ノートが見つからないときは従来表示のまま（フォールバック）

### 8.3 自分のノートが主役（v0.14 で「写真」から「起こした本文」へ）

```
┌ マストヘッド ── 日付 / 教科 / 単元 ─────────────────────┐
│ [想起問題だけ|自分のノートだけ|AIの添削も] [確認モード][解答を閉じる] │
├──────────────────────────────────────────────────────┤
│ 想起問題                  ← 自作が先、AI が後              │
├──────────────────────────────────────────────────────┤
│ キュー欄 │ 本文 = 自分のノートの再現   ← ここが紙。影を落とす │
│  重要語  │   └ AIの添削（紫・畳める）                     │
├──────────────────────────────────────────────────────┤
│ まとめ（自分の言葉。ノートに無ければ欄ごと出ない）           │
│ 疑問（自分の言葉）/ 連絡 / 演習（AI）                       │
├──────────────────────────────────────────────────────┤
│ ▸ ノートの写真 2 枚（原本）  ← 畳んである                    │
└──────────────────────────────────────────────────────┘
```

v0.13 では**写真**が主役で、AI の補足がその下に付いていた。v0.14 では
**起こした本文**（`sections[].text`）が主役になり、写真は「原本の控え」として最下段に畳む。
写真は読み返せても、色付け・確認モード・キュー欄という仕組みが一切効かないため
（§3.8）。開けば従来どおり `max-height: 50vh` の紙として出る。

3 つの約束（`globals.css` の `[E-3]`）:

1. **書体が著者を示す。** 自分の言葉（本文の `text`・自作の問い・疑問・まとめ・写真の見出し）は
   `--f-hand`（Klee One）、AI の添削（`ai`）と演習は `--f-ui`（BIZ UDPGothic）、表札は `--f-num`。
   読む前に「これは誰が書いたか」が分かる。**この画面以外で `--f-hand` を使わないこと** ――
   手書きに見えることが「自分の言葉」の合図として働かなくなる。
2. **色が層を示す。** 添削は紫インク（`--nb-ai-ink`）＋左罫（`.nb-aiedit`）。
   地の文の墨と混ざらない色で、重要語の 3 色（`--pink` / `--blue` / `--grn`）とも衝突しない。
3. **既定のレンズは「自分のノートだけ」**（`state.nbLens` の初期値が `'mine'`）。
   自分で書いたものを読み返すのがいちばん復習になる、という立場を既定にしたもの。

レンズ（`state.nbLens`）は 3 段。**左から順に出す量が増える**並びでスイッチに置く:

| 値 | 表示 | 出るもの |
|---|---|---|
| `'recall'` | 想起問題だけ | マストヘッド ＋ 想起問題だけ |
| `'mine'`（既定） | 自分のノートだけ | ＋ 本文の再現・まとめ・疑問 / 連絡・写真 |
| `'ai'` | AIの添削も | ＋ 各区画の添削（紫）・AI だけの区画・演習 |

`'recall'` で畳むもの / 残るもの:

| 畳む | 残す |
|---|---|
| コーネル本文（キュー欄ごと）・演習・疑問 / 連絡・写真・**まとめ** | 想起問題（自作・AI とも）とその解答・復習の予定 |

まとめまで畳むのは、**紙面を読めば答えが割れてしまう**から。「思い出せるか」を試す 1 周目の面で、
思い出せなかった問いだけレンズを戻して本文を読み直す、という順に使う。
本文もキュー欄も無いので**確認モードのボタンは出さない**（伏せる相手がいない）。

`'mine'` で畳むもの / 残るもの:

| 畳む（AI のもの） | 残す（自分のもの） |
|---|---|
| `sections[].ai`（添削） | `sections[].text`（本文の再現） |
| `text` が空の区画（AI だけの補足）ごと | `summary`（**自分が書いたまとめ**。v0.14 で残す側へ移った） |
| `exercise`（演習） | `doubt` / `notice` / 想起問題（自作・AI とも） |

- 想起問題はどのレンズでも `origin` にかかわらず残す ―― ここを畳むと復習ができない。
- **編集中はレンズを無視して全部出す**（`edit ? 'ai' : state.nbLens`）―― 畳んだ欄は直せない。
- レンズを「AIの添削も」に倒すと、紫の添削が本文の各区画に挟まって出る。

読みやすさの手当て（v0.13。「色と字が見づらい」への対応）:

| 前 | いま | なぜ |
|---|---|---|
| 本文 15px | `--nb-size: 16.5px` | ここは読む画面で、目を走らせる画面ではない |
| 重要語を差し色で塗る | 墨のまま太らせ、**色は下 4 割の蛍光帯**が持つ | 10 語塗った時点で本文が読めなくなっていた |
| キュー欄 12.5 / 10px | 13.5 / 11px、語は `--f-hand` | 左段が小さすぎてキューとして読めなかった |
| 写真が主役（50vh の紙） | 最下段に畳む | 仕組み（色・付箋・キュー）が効くのは本文だけだった |

紙面の切り替えにも動きを付ける（v0.15）。レンズを倒すと区画がまるごと入れ替わるので、
マストヘッドより下（`.nb-sheet`）に他画面と同じ `inkIn` を `.2s` で掛ける
――「押したスイッチの下だけが刷り直される」見立てなので、マストヘッドと読み方の列は動かさない。
実装は `NoteView` の `key={lens}` による mount し直し。解答（`.nb-ans.is-open`）にも同じ動きを
足した ―― キャレットが `.3s` で回るのに中身が瞬時に出るとちぐはぐだったため。
どちらも `prefers-reduced-motion: reduce` で `animation:none`（[E] の全体対応は transition にしか効かない）。

写真の操作は編集モードだけ（`＋ 写真` / 見出し / `この写真を削除`）。
拡大は同じ画面に重ねる（`.nb-zoom`。Esc か背景クリックで閉じる）。
ノートを削除したら `deleteNoteScans` で IndexedDB の実体も落とす。
本文の区画（見出し・`text`・`ai`）も編集モードで直せる ―― 再現がずれていたら
自分で直せることがこの設計の前提（AI の起こしは下書きであって、正本は自分の手で決める）。

### 8.5 想起問題の記録（`NoteCard.attempts`）

想起問題は**解くたびに 1 行残る**。

```ts
interface NoteAttempt { day: ISODate; grade: 'high' | 'mid' | 'low' }
```

復習行（`Review`）は完了すると次の行に置き換わっていくので、「この問題を何回やって、
そのときどう感じたか」は**ノート側に書かないと辿れない**。予定（次はいつ）と実績（何回・どうだった）
を別々に持つ、という切り分け。

書き込む場所は 2 つだけ:

| 経路 | 誰が呼ぶ | 復習の予定 |
|---|---|---|
| 予定どおりの復習 | `ReviewShared.completeReview`（理解度モーダル / ドリル面の共通路） | **動く**（次の間隔へ） |
| 予定の外の解き直し | 問題抽出の ◎○△（`recordNoteAttempt`） | **動かない** |

問題抽出で予定まで動かさないのは、「ちょっと解き直しただけ」で次回が飛んでしまうため。

記録の見え方:

- ノート（読む面）… 各問の脇に「3回 · 前回 8/9 ◎」。ホバーで全履歴
- ドリル面 … 「これまで3回 △ △ ◎」（直近 4 件を記号で）
- 問題抽出 … 同じ 1 行 + それを使った並べ替え・絞り込み

### 8.6 問題抽出の並べ替え（`lib/logic/noteExtract.ts`）

| 並び | 規則 |
|---|---|
| `weak`（既定）「苦手な順」 | **不安 → 未着手 → まあまあ → ばっちり**。同じなら久しく解いていない方が先 |
| `stale`「久しぶり順」 | 最後に解いた日が古い順（未着手が先頭） |
| `note`「ノート順」 | 取り込んだ形のまま（授業日の新しい順 → ノート内の並び） |

- 見るのは**直近の 1 件だけ**。過去に不安でも、最後がばっちりなら後ろへ回る。
- 未着手より「1 度やって不安と答えた問題」を先に出す。取りこぼしがはっきりしている方を先に。
- 演習（`note.exercise`）はカードではないので記録を持たない。`weak` / `stale` では
  **常に想起問題のうしろ**に回す（そうしないと「未着手」として毎回上位に居座り続ける）。
- 理解度チップ（すべて / 未着手 / △ / ○ / ◎）で絞れる。件数はチップに出す。
- 記録を付けると解答は伏せ直される。並べ替えが即座に効くので、次の 1 問がそのまま上に来る。

## 12. 既知のリスク

1. **dataPatch M3 のシングルトン系列**: 完了履歴を手動削除して系列が1行だけになると `seriesId` が
   自分の id へ書き換わり、リンクが切れる。→ 理解度モーダルはフォールバック表示になるだけで壊れない。

   サイドバーの設定から1クリックで止められるようにする
5. **時間割の教科名（英コ等）とノートの教科名（英語等）の不一致**: 統一しない。どちらも自由文字列で、
   色は `ShellSubjects` が自動採番する
